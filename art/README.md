# 美术协作目录（art/）—— ThinCoder 策划 ↔ Codex 美工

> 双方都读这个目录，**不用老板居中传话**。
> 需求方（策划）：ThinCoder 主 Agent。供应方（美工）：Codex。
> 项目：`D:\Study\MyProject\MyGame2`《空间站大停摆》（原创关卡 L1）

## 目录约定

| 路径 | 谁写 | 内容 |
|---|---|---|
| `art/tasks/` | **策划** | 任务单（TXX-名称.md）：规格、参考图、交付路径、验收标准 |
| `art/requirements-v1.md` | **策划** | 美术需求总表（全盘安排：优先级 / 依赖 / 规格与界面接口；含美工任务检查清单） |
| `art/deliveries/` | **美工** | 交付物：图片 + 可选 `notes.md`（说明哪张是哪张、遇到的问题） |
| `art/status.md` | **策划** | 任务单状态总表（下发 / 已交付 / 已验收 / 需返工），美工可读 |
| `images/station/` | **策划（验收后入库）** | 游戏真正使用的成品图；美工**不要**直接往这里写 |

## 美工方的交付规则（Codex 请照此办）

1. 读 `art/tasks/` 里状态为「下发」的任务单，按下单顺序做；
2. 图片存到 `art/deliveries/`，文件名 = `任务号-名称-v版本号.jpg`（例：`T01-deck1-scene-v1.jpg`；多张用 v2、v3）；
3. 同名交付可覆盖同一版本号；新尝试请递增版本号，**不要删除旧版本**；
4. 有疑问或需要更多参考，在 `art/deliveries/notes.md` 里写清楚（中文即可），策划会回；
5. 交付后在 `art/status.md` 的「美工备注」列填一行（可选，策划也会自己看目录）。

## 验收流程（策划）

`下发` → 美工出图（`已交付`）→ 策划逐张检查（风格一致性 / 无文字 / 尺寸 / 构图是否够用）→
- 通过：复制进 `images/station/` 并登记（`已入库`）；
- 不通过：在 `status.md` 写明原因（`需返工`），美工按新版本号重出。

## 通用硬规则（所有图都适用）

- **画面中不得出现任何文字、数字、标签、水印**（道具/人物图也不许有字）；
- 风格统一：以 `images/station/station-map-ai-v1.jpg` 为准（等距剖面 / 扁平半立体 / 柔和阴影 / 明快配色 / 细节丰富）；
- 尺寸：横构图宽 1600~2048px；单图 ≤ 1.5MB（JPEG）；
- 每张图只表达一个主体，不拼贴（需要网格拆分的任务单会明说：如人物图、道具图）。
