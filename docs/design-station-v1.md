## 3. 剧情大纲（三幕 + 3 结局）

**开场**：你来『晨星号』实习的第七天，晚餐刚端上桌——全站断电、警报响起、**氧气开始减少**。

- **第一幕·摸黑求生**（0~30%）：找到手电/工牌/氧气瓶，认识乘员；发现主供电是**被人为拔掉的**——不是事故。
- **第二幕·重启反应堆**（30~70%）：重启需要三件事，各有两条以上路径（防卡死）：
  - 控制芯片：① 老布给（帮他找零件）② 糖糖带你走维修爬道去实验室自己拿
  - 冷却剂：仓库（桑尼阻挠）→ ① 铁头开门硬拿 ② 用站猫罐头收买他的猫/或用账本把柄
  - 站长授权卡：① 医务室找阿雅（站长受伤被救）② 气闸舱（站长被困）
- **第三幕·真相与选择**（70~100%）：证据 + 授权到位后面对桑尼——
  - 结局 A **圆满**：重启反应堆 + 揭发桑尼 + 全员安全（需要证据 + 资源充足）
  - 结局 B **取舍**：反应堆重启成功，但桑尼乘救生舱跑了（证据不足/耽搁太久）
  - 结局 C **撤离**：反应堆来不及修，你带全员进救生舱撤离（全员生还，站放弃）——前置：检查过逃生舱 + 已广播集合（§8.5）
- **失败**：氧气 ≤ 0（"眼前一黑……"，44 号结算）；**星币不再判失败**（花光只到 0，不结算）；剧情性失败保留 29 号（收封口费后再进反应堆舱被桑尼埋伏）。

**② 标定：每房交互点（pins）**

- 每房 pins＝**自指 pin**（`pins[<本房节点号>]`——锚在房内主构件，避让既有 pins 与浮现锚点；**数据保留为校准锚点**；渲染面按 `design-ui-v1.md` §6.5：房间不渲染不可点编号圈（自指 pin 通常不可点 ⇒ 不出现）、不承担「你在这里」与遮罩开孔——B128 口径）＋**出口 pin**（该层大厅：顶层 18／中层 20／底层 21——锚在图中舱门/出口构件）＋**房内交互点 1~3 个**（从该房节点可见选项的可达目标中挑：图上有对应构件者——控制台／保险柜／堆芯／货架／管线等；纯文本选项不标 pin，不造图不新增语义）。
- 格式＝`pins: { '<节点号>': [x, y] }`（原图像素、与既有 pins 同口径；点击走 `navViaPin`／`pinChoiceIndex` 同一路径）。
- 标定方式＝**手标**：`C` 键校准模式在图上点读坐标（既有能力）；`detect-pins` 不适用于内景（它检测浅色圆形编号徽章，内景无文字徽章）——个别图若带显式圆形标记，可先跑检测再人工复核（工具保留）。
- 验收＝① 坐标在图内且与图上构件对拍（截图/目检）；② 出口 pin 目标＝本层大厅；③ 房内 pin 目标＝该房可见选项的可达节点（机检 `pinChoiceIndex ≥ 0`；自指 pin 豁免——不要求可点）；④ **每房含自指 pin**（键＝本房节点号——机检；数据锚点；标记/开孔载体口径由 `design-ui-v1.md` §6.5 收窄）。

**③ 衔接与回退：大厅/走廊 → 内景 → 返回**

- 进房：楼层/走廊场景点门 pin（或选项）→ 房间节点 → `syncScene` 取 `node.scene` → 场景切至内景。

## 8. 体验层整改（v2 · 2026-10-01）

> 来源：`station-rework-v1.md`（老板已批准）＋ `playtest-01-report.md`（P1~P12）。本文给"改到什么程度"的定值；逐句文案与提示分级见 `design-station-nodes.md` §8。

### 8.1 星币经济：断循环

**现状（bug）**：洗碗 +2 星币/−5 氧、料理 3 星币→+10 氧 ⇒ 每 3 星币净赚 +2.5 氧，可无限刷（证据 `station.js:172-173`）。

**改法（提价方案）**：

- 料理 **3 → 5 星币**；重复劳动的氧/星币汇率统一 2.5（洗碗 +2/−5；老布打下手 +3→**+2**/−5）；
- 自动贩卖机（食堂）货架：合成料理 5 星币、**备用电池 5 星币**（星币的"工具"等价物；中层大厅不再送电池，只留氧气 +5）；
- 星币可花到 0、花光不判失败（`coins.fail: null`，移除 `noSpendToZero`）。

**算式**：劳动 1 星币成本 = 5/2 = **2.5 氧**；料理 1 星币产出 = 10/5 = **2.0 氧** ⇒ 2.0 < 2.5，循环必亏。
一轮"洗碗×3 → 买 1 盒 → 吃掉"= −15 + 10 = **净 −5 氧**；断言 20 轮 = **−100 ≤ 0** ✓。

**不做**（另两个方案）：料理限量（20 轮断言失去意义、星币失去等价物）；料理不回氧（料理变死物）。洗碗软上限也不加（换钱是防卡死兜底，与料理侧无关）。

**货币显示口径（B77＋R2·裁定 1）**：玩家可见的金额一律写成「<数字> 枚星币」（与既有「＋2 枚星币」同构；只在 unit-only 渲染位补币种名）：商店行、购买对话框、付款理由串、废料回收、`--player` 商店行与付款尾注。**R2 追加（B78）**：① `--player` 余额行＝数字式 `🪙 星币 <N>`（不再用档位词）；② 拒付理由＝数字式——"星币不够（需要 N 枚星币，还差 K 枚）"；③ 资源读数一律数字式（氧气＝条＋数值——B04 重订，§8.3）。**数据面 `unit: '枚'` 不动**；帮助里「开局 20 枚」等自明处不改。

**失败与 45 号**：星币侧不再有失败结算；45 号编号**改为保险柜事件节点**（R10 的反馈落点，保住 45 点网络计数）。剧情性失败保留 29 号（收封口费后再进反应堆舱被桑尼埋伏）。

### 10.2 选项规则（可尝试 vs 隐藏 · B03 新哲学）

> B03 起，本关的选项只有两种呈现：**可点** 或 **不显示**——「灰显」不复存在（老板 2026-10-02 裁定：**锁定/未达理由**写在剧情里，不写在按钮上——适用面＝原 `lockText` 一类"为什么做不了"；**危险选项的选择前暗示**（D17；如 10③）允许保留在按钮文案里，两类分开）。
> **判定句：玩家此刻是否知道 / 有理由做这件事？** 是 ⇒ 可尝试；否 ⇒ 隐藏。

| 类 | 判定 | 呈现 |
|---|---|---|
| 甲 · 可尝试 | 玩家此刻有理由做的动作；条件不足只是"还没成" | **可选**：条件满足 ⇒ 成事推进；条件不足 ⇒ 原地失败反馈（`say` 一条，零代价、不可刷） |
| 乙 · 未知 | 选项依赖的人/事/物玩家此刻还不该知道（含剧透） | **隐藏**，直到获得相应知识/道具 |
| 丙 · 完成态 | 已做过 / 已拿到 / 已学到 | **隐藏**（`once`／完成后条件恒假） |
| 丁 · 消耗尽 | 消耗品用完（含"手边没有"） | 归甲：可尝试 + 反馈（"你摸了摸口袋——空的。"） |

- **判定句怎么用**：先问"玩家此刻知道什么"（对照 `station-story-bible.md` §4 信息顺序表），再问"这件事他有没有理由做"——知道且有理由 ⇒ 甲；不知道 ⇒ 乙。**与条件够不够无关**：条件不够只改*结果*，不改*可见性*。
- **失败反馈规范**：一条 `say`（玩家向、无数字、无内部词，回答"谁拦你、发生了什么"）；**原地停留**（`to`＝本节点自指——沿用既有约定：节点行 11①→11、圣经 §7.4 4③ `to: '4'`；无 `toIf`／`back`）；**零代价**（不写 `fx`）；**不写 `once`**——重复点只重放文案，不可刷。
- **数据形状＝互补双条目**：同一动作两条目——成事条目（原条件与后果不动）＋失败条目（条件＝成事条件的补集 ∧ 未完成）。两条目条件**必须两两互斥**（同一时刻至多一条可见）；同一动作有多个"拦你"状态时，失败条目按互斥条件拆多条。
- **完成态收口**：所有条目都并「未完成」谓词（`noItem`／`noKnows`／`notPinsAll`…）——完成即齐隐；`lock`／`lockIf`／`lockText` **归零**（E12 数据面停用；§7 v0.5 备注）。
- **验证分工**：数据面（可见/隐藏、条件互斥、文案）由 lint（§10.5）＋回放机检；**呈现面**（灰显是否真的不再渲染、"可尝试"按钮的交互）依赖**界面批 U 类**复核（口径见 nodes §9.7）。
- **盘点**：旧锁定项 26 处逐条重做＝`design-station-nodes.md` §9.7（可尝试 22／隐藏 4；失败反馈文案全表）。

**完成态判定的手段（B03 重订——原「三种工具」随灰显取消调整）**：

- **`once`（E6）**：该选项**执行过**即隐藏。适用：单路径、执行态即完成态（如 9①、17①）；同节点多选项可**共享标记名**天然互斥（4③/4④ `急救箱开过`）。边界：不知道「另一条路」完成——跨路径不覆盖。
- **`cond` 并条件**：把「未完成」谓词（`noItem`／`noKnows` 等）**并入每条目 `cond`**——完成即 `cond` 恒假 ⇒ 隐藏。适用：**成果可由多条路取得**（冷却剂罐／控制芯片／太阳能板已修好……）——谓词取全局物品/知识，任一来源完成即关闭；跨路径收口的唯一稳解。
- **`lockIf`（E12）：数据面停用**——B03 起全关 `lockIf` 与 `lock` 均为 0 处；其原"未完成灰显／完成隐藏"语义由「成事＋失败双条目」（§10.2）承担，完成态由两条目各自的 `cond` 承担。引擎能力保留（示例关 `dalim.js` 仍在用 `lock`），本关不写。
- **选择次序**：① 单路径、执行态 → `once`；② 成果多路可取得 → `cond` 并「未取得」；③ 未完成时要有反馈（旧"指路"位）→ 加失败条目（§10.2）。
- **坑位提醒**：`lockIf` 停用后，凡"完成后应隐藏"的条目必须**显式**并入 `cond`——漏并即完成后仍可点（旧 B34~B37 修的就是这类残留；全扫表＝nodes §9.3-C）。

### 10.5 一致性 lint 规格（6 条 · 可机器判定）

> 落点＝`prototype/test.station.mjs` 新增段；判定式可直接翻成断言。

**L1 同一角色多地同现**

- 判定式：每角色恰一处 `spot`；地点节点的 `chars` 引用须与 spot 同场景、且 spot 距该节点 pin ≤150 设计像素（同房间容差）；事件节点 `chars` 须登记在【角色在场表】（nodes §9.4）；每角色至少出现一次。
- 正例：铁头 spot＝4 号 pin（距离 0）→ 4 号 chars 通过；40 号（事件）登记 (tietou,40) 通过。
- 反例：胖胖 spot＝1 号 pin，而 5 号（观景厅）chars 含 pangpang（距离 ≈1100px）→ 报“角色多地同现”（现状即反例；处置：5 号移除）。

**L2 可见性两态（原「once 选项仍可见」· B03 重订）**

- 判定式：① 静态——全关 `lock`＝0、`lockIf`＝0、`lockText`＝0；「一次性语义」选项（清单＝nodes §9.3 组一/组二）须做到**完成后齐隐**——由显式「未完成」谓词（`cond` 恒假）或条件互补／终局蕴含保证（结果口径）。② 互补——每个"可尝试"站点：成事与失败条目条件两两互斥，且「未完成」时恰有一条可见、完成后齐隐（逐条模拟断言，含交叉完成路径）。③ 形状——失败条目：有 `say`、无 `fx`、无 `once`、**无跨节点去向**（`to` 仅本节点自指）、无 `toIf`／`back`／`battle`／`random`（原地、零代价、不可刷）。
- **豁免登记（B03 评审 #3）**：14③、8①b——隐藏式、只有 `cond` 无 `once`（`cond` 内即含未完成谓词：`noItem` 监控回放/账本 ⇒ 完成即恒假）；9① F1/F2、12③ F、16⑤ F、17③ F1/F2、40④ F1/F2（失败条）——由条件互补或终局蕴含关闭；11②、13②、14②——可重复项（§9.3 组三），不属一次性清单。
- 正例：10①（成事：`knows 铁头已开门`∧`noItem 冷却剂罐`；失败两条：未开门×未走 32／未开门×已走 32——互斥）——未开门可点→反馈、开门后成事、拿到后齐隐。

**L3 跨层跳跃（白名单外）**

- 判定式：任一去向（`to`/`toIf[].to`/`battle.winTo·loseTo`/`random[]`）的源场景≠目标场景时——地点节点：须命中 R1 白名单节点对且文案含通道词（电梯｜爬道｜舱）；事件节点：按发生场景表取源场景（默认＝入口场景；事件正文自述跨层者以发生场景表为准——R2 问题 16③），跨层去向在正文/选项点出所用通道即判过（事件内的叙事转场；目标不必是通道端点）；`back`、结局/失败豁免。

**L4 动作选项缺代价标记（B03 补失败条目口径）**

**L5 文本提到未出现过的名词**
