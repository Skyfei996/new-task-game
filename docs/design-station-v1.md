## 2. 世界观与角色

**设定**：星历 2187 年，木星轨道的补给中继站「晨星号」（环形三层结构：外层生活区 / 中层工作区 / 内层核心区）。你是趁暑假来参观的**实习生**——站上最小的乘员，编号 09，名叫**林小晨**（大家都叫你小晨；开场可以改成你自己的名字）。

**基调**：冒险 + 搞笑。合成料理难吃到出名、维修机器人有性格、站长养了一只不吃合成粮的站猫。

## 3. 剧情大纲（三幕 + 3 结局）

**开场**：你来『晨星号』实习的第七天，晚餐刚端上桌——全站断电、警报响起、**氧气开始减少**。

- **第一幕·摸黑求生**（0~30%）：找到手电/工牌/氧气瓶，认识乘员；发现主供电是**被人为拔掉的**——不是事故。
- **第二幕·重启反应堆**（30~70%）：重启需要三件事，各有两条以上路径（防卡死）：
  - 控制芯片：① 老布给（帮他找零件）② 糖糖带你走维修爬道去实验室自己拿
  - 冷却剂：仓库（桑尼阻挠）→ ① 铁头开门硬拿 ② 用站猫罐头收买他的猫/或用账本把柄
  - 站长授权卡：① 医务室找阿雅（站长受伤被救）② 气闸舱（站长被困）
- **第三幕·真相与选择**（70~100%）：证据 + 授权到位后面对桑尼——
  - 结局 A **圆满**：重启反应堆 + 揭发桑尼 + 全员安全（需要证据 + 资源充足）
  - 结局 B **取舍**：反应堆重启成功，但桑尼乘救生舱跑了（证据不足/耽搁太久）
  - 结局 C **撤离**：反应堆来不及修，你带全员进救生舱撤离（全员生还，站放弃）——前置：检查过逃生舱 + 已广播集合（§8.5）
- **失败**：氧气 ≤ 0（"眼前一黑……"，44 号结算）；**星币不再判失败**（花光只到 0，不结算）；剧情性失败保留 29 号（收封口费后再进反应堆舱被桑尼埋伏）。

## 5. 道具、经济与战斗

**道具（23 件：数据 20 件 + 本批新增文本道具 3 件；完整清单见 `design-station-nodes.md` §3）**：手电、工牌、氧气瓶、万能扳手、磁力靴、焊接枪、电击棒、机械手套、应急盾、控制芯片、冷却剂罐、站长授权卡、备用电池、医疗包、绳索、站猫罐头、合成料理、桑尼的账本（证据）、监控回放、反应堆安全规程、站长的便条、逃生舱钥匙、星尘矿石。
**武力装备（3~4 件）**：焊接枪（+1）、电击棒（+2）、机械手套（+1）、应急盾（+1）——对手：失控维修机器人（1）、安保机器人（3）、桑尼的无人机（6）
**线索（知识解锁）**：维修代码、反应堆安全规程、桑尼的走私暗号
**经济**：星币 20（普通）/ 15（困难）；自动贩卖机（食堂）卖合成料理 5 星币、备用电池 5 星币；赚钱＝帮胖胖洗碗 +2、给老布打下手 +2（都要耗氧 5）——**单一劳动 2.5 氧/星币 > 料理 2.0 氧/星币，任何"劳动→买吃的"循环净收益为负**（算式见 §8.1）。
**失败条件**：氧气 ≤ 0（44 号）；**星币不设失败**（`fail: null`，花光只到 0）；剧情性失败＝29 号。

## 6. 防卡死设计（老板点名要求 —— 硬规则）

| # | 规则 | 说明 |
|---|---|---|
| 1 | 关键道具**不可消耗、不可出售、不可丢失** | 沿用"红框"机制 |
| 2 | 每个门槛**至少两条解法** | 三件重启物的路径已按此设计（§3） |
| 3 | 经济**不枯竭也不失控** | 赚钱途径不枯竭（洗碗/打下手随时可做）；氧气补给 3 处 + 热食 2 份；任何循环净收益为负（§8.1） |
| 4 | 失败条件**始终可达** | 真卡住时，资源耗尽会自然走向失败结算（不会"永远挂着"） |
| 5 | 引擎兜底**走投无路检测** | 当前节点无可执行选项、无可达编号、无可用资源 → 弹"求救面板"（回到安全屋 / 重开本关） |

## 7. 本作需要的引擎能力（v0.2，实现时再拆技术方案）

1. **多关卡架构 + 关卡选择页**：启动页列出关卡（含《勇闯大里姆》），每关独立数据/素材/存档
2. **可配置资源与失败条件**：资源表（名称/图标/初始值/失败规则，含"归零不判失败"声明）+ 失败结算文案（本作＝星币 + 氧气；星币花光不判失败，见 §7 v0.3-E1）
3. **走投无路检测与兜底出口**（§6 第 5 条）
4. **玩家名**：开场（选难度页）输入框（默认「林小晨」），姓名存进存档；任务点文本支持占位符 `{me}`，渲染时替换成玩家名（乘员对话里用）
5. （后续里程碑）音效与音乐钩子
6. **多场景共用点**：同一编号点出现在多个场景的 pins（如电梯井）→ 该点无固定区域、保持当前场景（`sceneOfNode` 遇多点命中则返回 null）；场景切换沿用 v1.2 的机制（跨区目标缀区域名 + 气泡 + 角标）

### v0.3 小能力（本批设计定值；E1~E9 已实现于分片 A，E10 归分片 C）

> 接口以本表为准；每条只做"数据字段 + 渲染/结算行为 + 边界"。已实现能力（多关卡 / 通用资源 / `{me}` / 卡死保险 / 多场景）不动。

| # | 能力 | 数据字段 | 行为 | 边界与旧行为 |
|---|---|---|---|---|
| E1 | 资源"不判失败" | `resources[].fail: null` | 该资源只钳到 0，不触发失败结算、不设 `bankrupt` | 缺省不写 = 旧行为；本作 `coins.fail: null`，同时移除 `noSpendToZero`（可花到 0、可花光） |
| E2 | 序章页 | `meta.prologue = { lines: [...] , image? }` | 新局进入前整屏显示一次；按钮「跳过 / 开始」；`{me}` 可替换 | 读档（继续）不重放；无该字段的关卡不显示；开场图未到 → 无图也成立 |
| E3 | 道具正文 | `items[].text`（多段用 `\n`） | 背包/物品里带正文的道具可点开只读面板（网页与**管理台试玩器**同享）；CLI 加 `read <道具名>` | 未拥有 → 明确报错；无 `text` → "这件东西没什么可读的"；阅读不改任何状态 |
| E4 | 提示分级 | `choice.hint: 'vague'｜'exact'｜'none'`（缺省 `vague`） | 引擎**不自动**往选项上附加效果/数值；锁定项显示 `lockText` | `exact` 白名单见 §8.3；不写 = vague |
| E5 | 灰显理由文案 | `choice.lockText` | 锁定项显示它（玩家向、无数字） | 没有 lockText 时用兜底，兜底同样不含数字：道具→"还差：X"、线索→"还不到时候"、资源→"还差点底气" |
| E6 | 一次性选项 | `choice.once: true ｜ '<标记名>'` | 执行过一次后该选项隐藏；写标记名时记入 `st.chDone['<标记名>']`（随存档），可被条件 `{ chDone: '<标记名>' }` 查询（供正文分叉引用） | 与 `lock` 可并存：条件未满足=灰显（lock+lockText），做过了=隐藏；写 `true` 时仅内部记录（不可查询）；旧存档无该字段 → 空 |
| E7 | 选项反馈行 | `choice.say`（一句话，支持 `{me}`） | 执行时作旁白：CLI 打印 / 网页 toast（加长停留）/ 管理台事件行 / 文案稿带出 | 不改状态；与效果日志并列、不重复 |
| E8 | 正文分叉 | `node.tIf = [{ cond, t }]` | 显示第一个满足条件的 `t`；都不满足用 `t` | 复用现有条件语言（含 E6 的 `{ chDone: '<标记名>' }` 与 `pinsAll` 等）；进房时求值一次；不设"再次进入"专用语法（取舍见 §8.6-D5）；六处 tIf 的 cond 见 nodes §8.2 |
| E9 | 商店折叠 | 无（渲染层） | 选项在上；商店/回收收成一行（"🛒 商店（点开）"）默认折叠 | 折叠不影响可点性（点开即可买）；CLI 不折叠；验收：1280×720 与手机竖屏首屏见选项 |
| E10 | 试玩器玩家模式 | `node tools/play.mjs --player` | 隐藏：资源数字（改定性档位）、武力面板、步数、计数、去向编号、机械理由；显示 lockText；**例外**：战斗选项显示与真实玩家一致的「你的武力值 X ≥/< Y」（白名单③，§8.3） | 禁用 `--json`/`load`/`auto`；会话存 `.playtest/player-session.json`；`save` 可用（留证据） |

### 8.1 星币经济：断循环

**现状（bug）**：洗碗 +2 星币/−5 氧、料理 3 星币→+10 氧 ⇒ 每 3 星币净赚 +2.5 氧，可无限刷（证据 `station.js:172-173`）。

**改法（提价方案）**：

- 料理 **3 → 5 星币**；重复劳动的氧/星币汇率统一 2.5（洗碗 +2/−5；老布打下手 +3→**+2**/−5）；
- 自动贩卖机（食堂）货架：合成料理 5 星币、**备用电池 5 星币**（星币的"工具"等价物；中层大厅不再送电池，只留氧气 +5）；
- 星币可花到 0、花光不判失败（`coins.fail: null`，移除 `noSpendToZero`）。

**算式**：劳动 1 星币成本 = 5/2 = **2.5 氧**；料理 1 星币产出 = 10/5 = **2.0 氧** ⇒ 2.0 < 2.5，循环必亏。
一轮"洗碗×3 → 买 1 盒 → 吃掉"= −15 + 10 = **净 −5 氧**；断言 20 轮 = **−100 ≤ 0** ✓。

**不做**（另两个方案）：料理限量（20 轮断言失去意义、星币失去等价物）；料理不回氧（料理变死物）。洗碗软上限也不加（换钱是防卡死兜底，与料理侧无关）。

**失败与 45 号**：星币侧不再有失败结算；45 号编号**改为保险柜事件节点**（R10 的反馈落点，保住 45 点网络计数）。剧情性失败保留 29 号（收封口费后再进反应堆舱被桑尼埋伏）。

### 8.3 提示分级（hint）与灰显措辞

- **三档**：`vague`（缺省，感官/力气式暗示，不给结果）、`none`（纯动作或纯移动，不给暗示）、`exact`（写明效果——白名单制）。
- **exact 白名单**（仅此三类）：① 商店明码（价格与货架）；② 已知道具的使用（例："吃一盒合成料理（+10 氧气）"；本作含 1 号④、20 号两处）；③ 战斗规则显示（"你的武力值 X ≥/< Y"——沿用示例关的透明决策，且让孩子敢打）。**③ 为白名单新增项**（R06/S3 原文只写"商店与已知道具"），待老板确认（见批次档 B01 §2 修正轮 1）。
- **引擎不自动附加**：选项上不自动出现"（获得 X）（−N 氧）"或效果数值；写什么由作者定，白名单外的选项一律 vague/none。
- **灰显措辞**：每条锁定项用 `lockText` 写玩家向理由——不含数字、不用"条件/线索/状态"等内部词；写"缺什么/还不到时候"。
- **走查口径与结论**：逐条清单、分类与统计以 `design-station-nodes.md` §9.2（B02 全节点走查表）为唯一口径，本处不再另列数字。
  - 主线选项"直接剧透产出" = 0 条；精确提示只出现在白名单三类（③ 为新增项，待老板确认）。
  - 锁定项 lockText 全覆盖：全关扫描；B02 补齐 5 处（3①、8①a、12③、13②、14②，见 `design-station-nodes.md` §9.5）。
- **--player 玩家模式口径**（给体验师）：隐藏资源数字（改定性档位：氧气 ≥50%"还好"、20~50%"有点闷"、<20%"快喘不上气"；星币 ≥5"能买点东西"、1~4"不多了"、0"花光了"）、武力面板、步数与计数、去向编号、机械理由；显示 lockText。**例外**：战斗选项保留与真实玩家一致的「你的武力值 X ≥/< Y」（白名单③；与网页版渲染一致）。

### 10.2 选项规则（灰显 vs 隐藏）

| 类 | 判定 | 呈现 |
|---|---|---|
| 甲 · 另一条路 | 通往某成果的合法路径之一，缺件在游戏内可获取 | **灰显 + lockText**（写差什么、去哪拿） |
| 乙 · 完成态 | 已做过 / 已拿到 / 已学到，再做无意义 | **隐藏**（`once`／完成后条件恒假／`lockIf` 不成立——E12） |
| 丙 · 对象未现 | 选项依赖的东西在剧情上还不该被玩家知道 | **隐藏**（条件不满足且不标 `lock`／`lockIf`） |
| 丁 · 消耗尽 | 消耗品用完 | **隐藏**（条件自然为假） |

- **门槛句**：玩家读完灰显理由**能指出下一步去哪拿** → 甲（灰显）；指不出 → 隐藏。
- **`lockIf`（E12，收口轮）**：`cond` 不满足时再判 `lockIf`——成立 ⇒ 灰显＋`lockText`（甲：仍值得指路）；不成立 ⇒ 隐藏（乙：已完成／已关闭，**交叉路径同样关闭**）。与 `once` 并存时二者同判：执行过 ⇒ 隐藏（E6）。**（完成态收口轮补注）**：`lockIf` 只在 `cond` 假时参与判定——「完成态」必须同时并入 `cond`（§10.4「三种工具」）。
- **`lockIf` 与四类的关系**：只用于"甲＋乙"合体项；甲类恒灰用 `lock`；乙／丙／丁类不用（条件不满足直接隐藏）。
- **甲＋乙选项（B02 十五处＋QA 轮 1 处＝十六处）**：3①、4②、4④、7②、10①、10②、12②、**12③**、13①、14③、15①、16②、16③、19①、19②、28①——`lockIf` 拆分：未完成灰显、完成隐藏（部分并带 `once`，同判不冲突；完成态谓词并 `cond` 口径见 §10.4；谓词与分类见 nodes §9.3-A/§9.3-B、§9.5-B31~B39、B45）。
- **lockText 全覆盖**：每条锁定项自写 lockText（玩家向、无数字、无“条件/状态”等内部词），不得依赖引擎兜底；B02 补齐 5 处（3①、8①a、12③、13②、14②，落点见 nodes §9.5）。
- **盘点**：全关逐条分类见 `design-station-nodes.md` §9.3（灰显项全表 / 一次性项全表）。

**完成态判定的三种工具（B02 完成态收口轮；配套 §10.2 四类判据）**：

- **`once`（E6）**：该选项**执行过**即隐藏。适用：单路径、执行态即完成态（如 9①、17①）；同节点多选项可**共享标记名**天然互斥（4③/4④ `急救箱开过`）。边界：不知道「另一条路」完成——跨路径不覆盖。
- **cond 并条件**：把「未完成」谓词（`noItem`／`noKnows` 等）**并入 `cond`**——完成即 `cond` 恒假 ⇒ 隐藏。适用：**成果可由多条路取得**（冷却剂罐／控制芯片／太阳能板已修好……）——谓词取全局物品/知识，任一来源完成即关闭；跨路径收口的唯一稳解。
- **`E12 lockIf`（配 `lockText`）**：`cond` 不满足时再判——`lockIf` 成立 ⇒ 灰显＋`lockText`（甲·指路）；不成立 ⇒ 隐藏（乙·已完成／已关闭）。适用：未完成时需要指路理由的「甲＋乙」项。
- **选择次序**：① 单路径、执行态 → `once`；② 成果多路可取得 → `cond` 并「未取得」；③ 未完成时还要指路 → 再配 `lockIf`（此时 `cond`＝门槛 ∧「未取得」，`lockIf`＝「未取得」）。
- **坑位提醒**：`lockIf` 只在 `cond` 假时参与判定——「完成态」必须**同时**并入 `cond`，否则 `cond` 为真时完成项仍可点（B34~B37 修的就是这类残留；完成态全扫表＝nodes §9.3-C）。

### 10.5 一致性 lint 规格（5 条 · 可机器判定）

> 落点＝`prototype/test.station.mjs` 新增段；判定式可直接翻成断言。

**L1 同一角色多地同现**

- 判定式：每角色恰一处 `spot`；地点节点的 `chars` 引用须与 spot 同场景、且 spot 距该节点 pin ≤150 设计像素（同房间容差）；事件节点 `chars` 须登记在【角色在场表】（nodes §9.4）；每角色至少出现一次。
- 正例：铁头 spot＝4 号 pin（距离 0）→ 4 号 chars 通过；40 号（事件）登记 (tietou,40) 通过。
- 反例：胖胖 spot＝1 号 pin，而 5 号（观景厅）chars 含 pangpang（距离 ≈1100px）→ 报“角色多地同现”（现状即反例；处置：5 号移除）。

**L2 once 选项仍可见**

- 判定式：① 静态——"一次性语义"选项（获得唯一来源道具/唯一信息/一次性事件；清单＝nodes §9.3）必须带 `once`、完成后条件恒假（消耗型/状态型）或 `lockIf` 完成态谓词（E12）；② 回放——对清单逐条模拟执行一次，甲＋乙项另按其交叉路径各模拟一次，断言其从 `visibleChoices` 消失，且重进节点仍不出现。
- 正例：11①（once '取了磁力靴'）执行后隐藏；16②（`lockIf` noKnows '机器人小帮手'）收编后隐藏（含经 16① 战胜的路径）；10①（`lockIf`＋once）未满足灰显、完成（自身或经 13/31/32）隐藏；13①（`lockIf`＋`cond` 并 `{ noItem: '冷却剂罐' }`）经 13③ 取罐后隐藏；19①/19② 互经另一条路修板后同步隐藏（完成态谓词并 `cond`——B34~B37）。
- 反例：修复前 12③/8②/16②（执行后仍可见、可重复领奖）→ 报；修复前 4②/10①（交叉路径完成后仍灰显、理由失真）→ 报；修复前 13①/19①/19②（`cond` 为真时完成态仍可点——完成态收口轮）→ 报。

**L3 跨层跳跃（白名单外）**

- 判定式：任一去向（`to`/`toIf[].to`/`battle.winTo·loseTo`/`random[]`）的源场景≠目标场景时——地点节点：须命中 R1 白名单节点对且文案含通道词（电梯｜爬道｜舱）；事件节点：按发生场景表取源场景（＝入口场景），跨层去向在正文/选项点出所用通道即判过（事件内的叙事转场；目标不必是通道端点）；`back`、结局/失败豁免。
- 正例：18→20「乘电梯去中层」；16→7「钻进维修爬道」；25→16「顺着维修爬道滑下去」；28→10／→20「搭电梯下到中层」（事件跨层·通道词）。
- 反例：修复前 25→16（无通道语义）、24→20、30→21、38→7 → 报“跨层跳跃”。

**L4 动作选项缺代价标记**

- 判定式：命中力气词表（撬｜搬｜拖｜推｜拽｜掰｜扛｜翻｜钻｜爬｜冲｜焊｜拧）的动作选项——命中以动作为准，通道名（「爬道」「电梯」）不计；其代价载体（选项 `fx` 或目标 `en`）须含氧气负值（≥5；攀爬类 ≥10），或在豁免表；所有 `battle` 选项必须带 `loseSay`。
- 正例：26① 修复后 −5；16④ −10；19① 经 39.en −5；25①/30① 滑降在豁免表（0 氧合法）。
- 反例：修复前 26①（“掰”命中、零氧耗、无豁免）→ 报。

**L5 文本提到未出现过的名词**

- 判定式：① 名词表词条不得早于“允许集”出现（扫描 node.t / tIf / 选项文案 / say / lockText / items.text / 序章 / 帮助 ＋导出文案稿）；② 首现句清单机器产出、人工/LLM 复核“当场解释”；③ 名词表无死条目。名词表（首现节点＋允许集）由叙事线维护、lint 读表。
- 正例：「保险柜密码」允许集 {23,35}，出现处均自带解释（“密码是 0325”）。
- 反例：修复前 28 号「货单上“猫粮”那一栏…」早于玩家见过 8 号货单 → 报“引用早于首现”（#5；整链重做归叙事线）。
