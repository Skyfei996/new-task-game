## 二、归类：4 个系统性问题（B02 要一次性解决的）

- **S1 选项与代价**：自动发放 vs 显式选项；动作要有代价；灰显 vs 隐藏的取舍
- **S2 角色与剧情一致性**：同一角色两地；**信息必须先见后推**；人物要立得住
- **S3 空间与移动规则**：跨层只能走通道；通道双向可读；场景内选项必须保留
- **S4 反馈与状态**：每次操作有反馈；一次性选项隐藏；状态变化有提示

## 三、为什么上一轮没测出来（诚实复盘）

1. **测试师的简报是"机制向"**：只要求"走到结局 / 找不通的路 / 失败一次"，**没有连续性检查清单**（角色在哪、信息顺序、空间常识）——所以它抓到了"保险柜没反馈""冷却塔纯亏"，却抓不到"胖胖分身""还没见货单就说对上了"。
2. **信息给多了**：报告 01 的测试师用的是**开发版 CLI**（带节点编号、精确数值、去向），很容易"看懂"；`--player` 是后来才做的，且仍保留节点编号。
3. **没有对抗式要求**：简报没有"最少提 N 条疑问""任何操作后画面无变化必须记为问题"，LLM 天然倾向**替作者圆场**。
4. **编剧侧缺"手艺关卡"**：设计只过了**方法学评审**（口径/一致性/可验收），没过**叙事手艺评审**（角色声音/因果顺序/空间常识/动作经济）；写文案时也没做"朗读"和"信息顺序表"这两道工序。

## 四、升级方案（让编剧与测试更像"人"）

### 编剧侧 · 4 道新工序
1. **故事圣经**（单一事实源）：谁能出现在哪 / 通道清单（双向）/ 动作耗氧表 / 道具因果链 / 每角色一张人物卡（职业·性格·特点·能力·喜好·口头禅 + 不会说的话）
2. **信息顺序表**：每个结论出现前，玩家必须**先看过它依赖的每个前提**（先见货单，才说得出"对上了"）
3. **朗读工序**：对白念一遍；每人说话长度/口癖/态度不同；胜、败、被拒都要有反应
4. **机器可查的一致性清单**（进自测）：① 同一角色多地出现 ② 选项重复（once 未隐藏）③ 跨层跳跃（白名单：电梯/爬道/舱外）④ 动作选项缺代价标记 ⑤ 文本提到未出现过的名词

### 测试侧 · 改简报 + 改人设 + 改节奏
1. **三种测试各一张清单**：逻辑（可达/状态）｜**连续性**（角色/时间/空间/因果）｜体验（无聊/困惑/想放弃）
2. **对抗式要求**：至少提 N 条疑问（每条引原文）；**"任何操作后画面无变化"必须记为问题**；禁止替作者解释；"这是原型/测试版"不能作为放过理由
3. **限制信息**：只给 `--player`；报告阶段才允许用编号定位
4. **专业人设**：把"10 岁小孩"升级成**有背景的小玩家**（玩过 20 款手游、容易烦、看不懂就跳过）；新增「**挑剔的编剧**」人设（专查连续性/声音/因果）与「**陪玩家长**」
5. **节奏**：每 15 步小结（已有）+ **每幕结束做一次复述**（"刚才发生了什么？我为什么这么做？"——复述不出来＝剧情不清楚）
