# 《空间站大停摆》体验层整改清单（v1 · 需求面）

> **来源**：老板真人试玩 10 条反馈（2026-10-01）+ 第 1 位 AI 体验师发现（`playtest-01-report.md` P1~P12）+ 主 agent 复核
> **状态**：待老板审 → 审完交设计（数值与逐句文案细化）→ 顾问评审 → 老板批准 → 实现 → 测试师复测 → **剧本定稿后停下等老板验收**（验收通过才下发美术/立项开发）
> **本清单只管"改什么、为什么、怎么验收"**；具体数值、逐句文案、提示词分寸在设计阶段定

---

## 0. 已定参数（老板裁定 2026-10-01）

| 项 | 裁定 |
|---|---|
| 货币名称 | **星币**（原名"信用点"作废——收封口费却增加"信用"，语义不通） |
| 货币失败条件 | **钱花光不判失败**（可以花到 0，不能为负）；剧情性勒索若"钱不够 + 武力不够"可设计为失败分支（看剧情需要） |
| 氧气压力 | **简单 = 中等**、**困难 = 紧**；必须做数值预算验算（机器保证不无解） |
| 选项提示 | **默认模糊**（例："可能要花点力气""里面像是有东西"）；允许少数精确（如商店明码标价、明确的道具使用）；也可完全不提示。分寸在设计阶段定——**拿不准就先全模糊** |

## 1. 五个系统性问题（本轮整改的主线）

| # | 问题 | 老板原话 / 证据 | 整改目标 | 验收标准 |
|---|---|---|---|---|
| **S1** | 开场没有"我是谁、这是哪、今天要干嘛" | "在哪里？我是说？平时是怎样的？" | 加**序章**（≤100 字）：身份、晨星号日常、今天的异常、眼下任务 | 序章文案经老板确认；新玩家读完能复述"我是谁/要干什么" |
| **S2** | 货币立不住：名字误导、概念没介绍、为 0 无后果感 | "这是信用？这能增加信用？""0 信用又怎么样了？" | 改名**星币** + 开场/玩法说明里讲清"能换什么" + 去掉"钱=0 判失败" + 花钱要**有明确的等价物**（吃、工具、情报） | 搜全库无"信用点"残留；星币在开场 5 分钟内出现一次自然解释；花光后不再触发失败结算 |
| **S3** | **选择没有代价 + 结果被剧透 → 没有探索与紧迫感**（最核心） | "每一个选项都点，一点代价都没有""看选项就知道拿到什么，那还有什么好思考的" | 选项**去精确化**（模糊提示）；**大多数选择都要有代价或风险**；关键收获不再写在选项上；"探索"重新成立 | 逐条走查：主线选项里"直接剧透产出"的 ≤0 条；≥70% 的选项带代价/风险/不确定；精确提示仅限"商店价格、已知道具的使用" |
| **S4** | 经济可无限刷、数值失控 | "无限洗碗无限买料理吃料理，不就吃到无限大了" | 断掉循环（见 §3） + 补充氧气支出点 | 新增**自动断言**：任何"收入→消耗"循环净收益必须为负；通关可行性在简单/困难各跑通 |
| **S5** | 反馈缺失：文本类道具没内容、逃生舱自相矛盾、商店挤屏 | "拿到账本但没打开看内容？""同一个地方就能满足另一个选项的条件？" | 道具**可查看正文**；修正逃生舱逻辑；商店折叠；UI 让选项优先 | 账本/规程/监控回放等可点开看到正文；逃生舱不再"同屋自解锁" |

## 2. 逐条改造清单

| 编号 | 问题（含证据） | 改法 | 验收标准 |
|---|---|---|---|
| R01 | 缺开场（老板①） | 新增**序章节点**（3~5 句 + 一张开场图另下美术单） | 序章 ≤100 字；老板确认 |
| R02 | 货币名与语义（老板②⑩） | 全库改名**星币**；开场解释"星币能换吃的和工具"；失败条件 45 号改为"剧情性惩罚"或删除 | 无"信用点"残留；45 号节点不再是钱=0 触发 |
| R03 | 商店挤屏（老板③） | 试玩器与游戏 UI：**选项在上、商店折叠** | 1280×720 与手机竖屏下，选项首屏可见 |
| R04 | 无限刷（老板④） | 断循环：料理**限量**（建议：每人 1~2 次/或改为"胖胖的热汤"限次）与洗碗**软上限**（胖胖"今天够了"）三选一，设计阶段定 | 自动断言：连续"洗碗→买→吃" 20 轮的净氧 ≤ 0 |
| R05 | 氧耗太少（老板⑤⑦） | 重新分配氧气支出：跑动/开舱门/举重物/蒸汽/黑暗摸索…让**每层都有支出**；一次性补给由 3 处维持但数值下调 | 简单：主线最短路径消耗 ≤ 可得补给 ×0.7；困难 ≤ ×0.95（预算表见设计档） |
| R06 | 选项剧透（老板⑧） | 选项文案分级：**模糊/无提示/精确**（精确仅限商店与已知道具）；灰显理由也去数值化 | 走查表：主线选项无"（获得 X）（−N 氧）"式精确剧透 |
| R07 | 文本类道具没内容（老板⑥） | 道具加 `text` 字段 + 查看面板（账本、反应堆规程、监控回放、站长的便条…） | 4 件以上文本道具可点开看到正文；正文经老板确认 |
| R08 | 逃生舱自相矛盾（老板⑨） | 结局 C 加**前置**（例：必须先广播集合/恢复电力/找到钥匙之一），删除"同屋自解锁" | 未满足前置时"启动撤离"锁定并给出**模糊**理由 |
| R09 | 房间切换不合理（老板"末"） | 短期：移动选项加方向感文字；中期：走廊/房间内景图到位后统一切场景 | 走查：连续两个移动选项的差异一眼可辨 |
| R10 | 体验师 P1（保险柜无反馈） | 保险柜给卡时**必须有文字**（新事件节点或文本行） | CLI 走一遍可见反馈 |
| R11 | 体验师 P2（观景厅重复文案） | 一次性效果配"只出现一次"的文案（文本分叉） | 二次进入文本不同 |
| R12 | 体验师 P3（冷却塔纯亏选项） | 给收益或删掉（设计阶段定：建议改为"快速通道 + 掉氧 + 可能擦伤"，保留风险感） | 无"零收益纯亏"选项（走查） |
| R13 | 体验师 P4（失败文案站名错） | "中继站"→"晨星号" | 全库站名统一 |
| R14 | 体验师 P5/P6（状态文案不更新） | 实验室/太阳能线加状态分叉文案 | 拿箱后、修板后文本不同 |
| R15 | 体验师 P7（断电无下文） | 给明确去向与文字 | 走查 |
| R16 | 体验师 P10/P11（空反馈/文字与选项不符） | 补对话文本；文本提到的东西必须可拿 | 走查 |

## 3. 数值与平衡（必须机器验算）

1. **断循环**：现行数据 `洗碗 +2 星币/−5 氧`、`料理 3 星币 → +10 氧` ⇒ 净赚 +2.5 氧/轮 ✗（实测证据：`station.js:172-173`）。设计阶段在三种方案中定一种（限量 / 提价 / 料理不回氧）。
2. **氧气预算表**（设计阶段产出）：主线最短路径逐段消耗 vs 可得补给，简单模式留 ≥30% 余量，困难模式留 ≤5% 余量。
3. **新增自动断言**（进 `test.station.mjs`）：
   - 循环净收益为负（R04）；
   - 简单/困难各跑通 ≥1 条主线到结局 A；
   - 结局 C 的前置未满足时确实锁死；
   - 计分/资源全程不为负。

## 4. 需要的引擎能力（小改动）

| 能力 | 说明 |
|---|---|
| 道具正文 | 道具表加 `text`；UI/CLI 支持"查看"（只读面板） |
| 提示分级 | 选项字段声明 `hint: 'vague'｜'exact'｜'none'`（缺省 vague），引擎只负责渲染 |
| 序章 | 关卡 meta 加 `prologue`（开场页），进关卡前显示一次，可跳过 |
| 商店折叠 | 选项优先，商店/回收收进可展开的一行 |
| 试玩器玩家模式 | `--player`：隐藏数值/下一步提示/锁定原因，与真实玩家所见一致（测试师专用） |

## 5. 体验测试师升级（人设 + 硬隔离）

1. **硬隔离**：独立会话启动（零上下文）；**只允许用试玩器 CLI**（`--player` 模式），禁止读代码/设计文档/文案稿；禁止重试掩盖失败。
2. **三个人设分别测**：
   - 🧒 **10 岁小孩**：好奇、乱点、没耐心，只做有趣的事；
   - 👨‍👩 **陪玩家长**：孩子能自己玩下去吗？会不会卡死？有没有看不懂/吓人的内容；
   - 🗺️ **全收集型**：想找齐一切，会抱怨"看不出该干嘛"。
3. **节奏纪律**：**每 15 步写一次玩家日记**（当时想干什么/感受 1~5 分/有没有想放弃），全部基于当时的原话；报告只讲人话（无聊/惊喜/烦/紧张/想笑），不写机制分析。
4. 复测在整改完成后进行，产出**简单 + 困难两份**报告。

## 6. 不在本轮范围

- 美术素材（等剧本定稿后统一下发：开场图 + 星币/道具图标 + 人物立绘 + 走廊/房间内景）
- 走廊/房间内景的分层切场景（等图到齐）
- 音效音乐

## 7. 交付与停下点

- **交付物**：改后的关卡数据 + 重新导出的文案稿 + 三套自测全绿（含 §3 新断言）+ 体验师两份报告；
- **停下点**：**剧本定稿后停止，等老板验收**——老板确认文案与体验无问题，才下发美术任务、进入正式开发。
