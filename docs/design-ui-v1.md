# 《空间站大停摆》界面与视觉设计（design-ui-v1）

> 归属：本关**界面 / 体验设计的唯一归属**——布局骨架、提示颜色语义、弹框与反馈规则、物品栏、氧气读数呈现、在场人物表现、舱外与空间通道的界面侧、玩法说明全文与检查清单。
> 权威关系：数值与预算＝`design-station-v1.md` §8；文案＝`station-story-bible.md` §7；画面演出与镜头＝`station-staging.md` §1；场景架构与出图规则＝`art/scene-architecture.md`。三者冲突 ⇒ 停下上报，不得就地改口径。
> 状态：**v1（B04 · 2026-10-03）设计完成**——待设计评审 + 老板批准；**未批准不进实现**。
> 来源：老板 2026-10-03 剧本定稿后的界面与体验 7 点意见 ＋ 美术任务全盘重排指令（「未处理的任务先全部撤回，重新安排……每改一次任务都检查美工的任务」）。
> 边界：本档只写「界面怎么摆、怎么反馈」；不改剧情语义与数值（需要新数据处一律走「最小新增」并论证）；不写实现代码。

---

## 0. 做法与理由（一页）

1. **不新语义**：七点意见全部落成「呈现层与交互层」的设计——剧情文本、条件、数值、结局一概不动；界面需要的数据一律优先复用现成字段。
2. **零 / 最小新增**：全批只有**一处数据面最小新增**——`node.cast`（在场人物的坐标覆盖，可选字段，缺省＝现行行为，见 §7）；其余全部用现成字段与渲染层完成。理由与边界逐条写在 §7。
3. **一屏原则**：任何时刻首屏要能同时看到——资源读数、场景与在场人物、正文、可点选项；新增的反馈区与物品栏都不许把选项挤出首屏。
4. **颜色必有冗余**：颜色只作第一眼区分；每一类消息同时带**图标 + 前缀词 + 固定位置**三件冗余，色盲玩家不靠颜色也能分辨（见 §3）。
5. **改动可机检**：颜色触发条件、弹框时长、物品栏内容、氧气数值与条的同步关系，全部写成可断言的判据（见 §3~§6 各表「机检」行）。

## 2. 七点逐条设计（B101~B107）

编号与批次档 §2 逐条对应（三链同源：本表＝批次档条目＝验收对照 §10）。

### B101 ① 人物在场可见

- **老板原话要点**：场景只有背景图，剧情里的人物/机器人/猫在界面上看不到，玩家没法代入。
- **落点**：§7（在场人物表现与数据来源）；`art/requirements-v1.md`（T05 切片）。
- **改法**：三处呈现位——① 场景区：头像（T05 切片）＋名牌＋光环；② 剧情区「👤 在这里」条（头像＋名字＋称号，可点开人物卡）；③ 图鉴/人物卡换真头像。数据＝`node.chars`（既有）＋可选 `node.cast` 坐标覆盖。
- **验收点**：40/28/29/38 四节点的场景区出现对应头像且坐标＝`cast`；其余节点回归不变；`bible §2.1` 在场表 ↔ 数据逐节点一致。
- **影响文件**：`prototype/engine.js`（`renderCharSpots`/`renderHereChars`/`charFace`）、`prototype/levels/station.js`（cast 条目）、`prototype/style.css`；切片产物 `images/station/chars/`。

### B102 ② 提示着色 + 弹框延时 + 剧情区反馈区

- **老板原话要点**：选项在右侧、提示只在地图处弹框且太快——弹框保留＋延时；右侧剧情区也要显示对应文字；用颜色区分（蓝＝正常、红＝未达条件、黄＝关键剧情——按其指示「按专业设计，不照搬」）。
- **落点**：§3（颜色语义表）＋§4（弹框与反馈区规则）。
- **改法**：消息分 4 类着色（info 蓝／gain 绿／key 金／fail 橙红）＋既有危险大条；每条带 `data-kind` 与图标/前缀冗余；toast 驻留加长；正文与选项之间新增**反馈区**（同源渲染、节点内常驻到下一次操作）。
- **验收点**：§3 触发 Hook 逐类可机检（learn→key、gain→gain、失败条形状→fail、其余→info）；toast 新时长；反馈区存在且与 toast 同串。
- **影响文件**：`prototype/engine.js`（`toast`/`doChoice`/`renderNode`）、`prototype/style.css`、`prototype/index.html`（反馈区容器）。

### B103 ③ 地图下方横向物品栏

- **老板原话要点**：地图下方加横向物品栏（不用开背包）。
- **落点**：§5（物品栏规格与交互）。
- **改法**：场景区底部新增横排；持有道具（`itemOrder` 序）＝图标＋名＋📖 角标；点选＝详情气泡；「看内容」＝既有只读面板；「使用」＝等价于点对应选项（唯一可用时直接执行，多条时滚动高亮），不做自由使用。
- **验收点**：§5 机检行逐条（内容＝`st.items`；使用按钮出现条件；点「使用」与点选项结果逐字一致）。
- **影响文件**：`prototype/index.html`、`prototype/engine.js`、`prototype/style.css`。

### B104 ④ 氧气条旁显示具体数值

- **老板原话要点**：氧气条旁显示具体数值（他要能算耗氧量）——**取代此前「无数字」口径**。
- **落点**：§6（氧气读数）；口径同步＝`design-station-v1.md` §8.3/§8.7-8（本批已改写，见 §11 变更记录）。
- **改法**：HUD 氧气＝条＋数值（数值＝当前余量，条＝数值 ÷ 基准 × 10 格取整，同源同帧）；`--player` 文本条同口径（工具面）。
- **验收点**：渲染串含数值；数值与条填充可对拍（fill ＝ round(v/100×10)）；扣/回氧同帧更新。
- **影响文件**：`prototype/engine.js`（`renderHUD`）、`prototype/style.css`、`tools/play.mjs`（工具面）、测试断言（见 §9）。

### B105 ⑤ 玩法说明重写 + 检查清单

## 3. 提示颜色语义表（B102 · 可机检）

**总规则**：每条玩家可见消息渲染为 `<span class="msg msg-<kind>" data-kind="<kind>">`；颜色只作第一眼区分，**图标＋前缀＋位置**三件冗余保底（色盲友好）。

| 类 | 颜色（token） | 形态冗余（图标/前缀） | 触发条件（Hook · 可机检） | 位置 | 样例（玩家所见） |
|---|---|---|---|---|---|
| `info` 常规 | 蓝 `--msg-info #4ea3ff` | 无前缀 | 其余效果日志与移动提示（效果日志中非「获得/失去」「🔑」开头者） | toast＋反馈区 | 「−5 点氧气」「🛗 到达：顶层」 |
| `gain` 获得 | 绿 `--msg-gain #4cc9a0` | 前缀「获得 / 失去」（数据自带） | 效果日志以「获得 」或「失去 」开头（`fx.gain`／`fx.lose`） | toast＋反馈区 | 「获得 医疗包 🩹」 |
| `key` 关键 | 金 `--msg-key #ffb703` | 前缀「🔑 记住了一条线索：」（数据自带） | 效果日志以「🔑 记住了一条线索：」开头（`fx.learn`／`en.learn`，含里程碑） | toast＋反馈区 | 「🔑 记住了一条线索：保险柜密码」 |
| `fail` 未达 | 橙红 `--msg-fail #ff7a59` | 前缀「✕」（UI 层加，不改数据文本） | 选项满足失败条形状：`say ∧ to===当前节点 ∧ ¬fx ∧ ¬once`（B03 失败条 26 条，`design-station-nodes.md` §9.7）⇒ 其 `say` 入本类；显式覆盖＝可选字段 `choice.sayKind:'fail'` | toast＋反馈区 | 「✕ 你推了推门——锁着。」 |
| `danger` 危险 | 红 `#e63946`／绿（被挡下） | 大号条＋既有文案 | `en.thief`（被偷）／`ifNoItem`（被挡下）——既有 `st.flash` | 剧情区顶部大条（既有） | 「🥷 桑尼的无人机 偷走了你 8 枚星币」 |

**要点**

- 颜色**不照搬**老板举例的蓝/红/黄三分：增加「获得」一类（绿），且「未达」用橙红（与致命红 `danger` 在色相与位置上双区分——danger 走顶部大条、fail 走小消息）。
- 冗余三件套：① 图标/前缀（上表）；② `data-kind` 属性（DOM 机检用）；③ 位置（fail/key/gain 进常驻反馈区，见 §4）。
- 语义判据「fail＝玩家尝试后没做成」与 B03 新哲学一致（条件不足不上按钮，失败在剧情里反馈）；本表只给它**配色与落位**，不改任何文案。

**机检断言（实现轮）**

1. 每条消息节点带 `data-kind` 且 ∈ {info, gain, key, fail}；
2. 26 条失败条的 `say` 均渲染为 `fail`（按上表形状枚举）；
3. `fx.learn` 产出均渲染为 `key`；`fx.gain` 均渲染为 `gain`；
4. CSS 中 `.msg-info/.msg-gain/.msg-key/.msg-fail` 四类颜色互不相同，且 `:root` 有对应 token。

## 4. 弹框（toast）与反馈区规则（B102）

**数字口径（改自现状）**：现状 toast 缺省驻留 3.4s（`engine.js:700`）、`say` 用 6s；老板反馈「太快」。

| 项 | 规则 |
|---|---|
| 时长 | `info`/`gain`＝**4.2s**；`key`/`fail`＝**7.0s**（信息量最大的两类给足阅读时间） |
| 同屏条数 | toast 同屏最多 **3 条**；超出时最早一条立即淡出（不堆叠遮挡） |
| 去重① | 同一次操作的 `say` 与效果日志文本相同 ⇒ 只显示一次（E7 既有口径，保持） |
| 去重② | toast 与反馈区**同源**（同一消息数组渲染两处），同文本不二次生成 |
| 去重③ | 同一节点内重复点同一失败条：toast 每次重新弹（操作要有回声）；反馈区**原位刷新**，不叠新行 |
| 反馈区位置 | 剧情区内、**正文与选项之间**（正文的下一条读得到） |
| 反馈区内容 | 最近一次操作的完整消息组：`say`（若有）＋效果行，合计 **≤4 行**；无内容时不占位 |
| 反馈区清空 | 进入新节点（`st.loc` 变化）或重开本关时清空；同一节点内只保留最近一次 |
| 既有警示条 | 被偷/被挡下大条（`#alertBar`）不动——它属于 `danger` 类，位置在顶部，与反馈区不冲突 |

## 5. 物品栏规格与交互（B103）

**位置**：场景区底部（地图正下方，桌面与移动端同一条），横向排布；条目多时横向滚动。

| 项 | 规格 |
|---|---|
| 条目来源 | `st.items`，按 `itemOrder`（数据既有）排序；**只显示已持有**（未持有不留灰位） |
| 单条形态 | 图标（道具切片）＋名称（≤4 字截断）＋角标：📖＝有正文；「可用」＝当前有唯一消费选项 |
| 空栏 | 显示「（还没有道具）」一行小字 |
| 点选 | 单击展开详情气泡：图标／名称／「📖 看内容」（有正文时）／「可用于：<选项名>」（命中时） |
| 查看 | 有 `text` 的道具 → 打开既有只读面板（E3，不变）；无正文 → 「这件东西没什么可读的」（不变） |

## 6. 氧气读数与其它呈现口径（B104/B109）

### 6.1 氧气＝数值＋条（同源同帧）

- **HUD 形**：`💨 [██████░░░░] 58`——图标＋10 格分段条＋数值。

- **边界**：帮助补给行等「效果量」数字保留（`design-station-v1.md` §8.3 口径不变）；开发视图（lab/CLI/JSON）不受限；资源数据与存档不动。
