## 0. 做法与理由（一页）

1. **不新语义**：七点意见全部落成「呈现层与交互层」的设计——剧情文本、条件、数值、结局一概不动；界面需要的数据一律优先复用现成字段。
2. **零 / 最小新增**：数据面新增＝**唯一清单（7 项）**——① `moments` 注册表（浮现图注册：id／文件／锚点／宽度；见 §7.3）；② 节点可选 `moments`／`mIf`（浮现图触发；缺省＝不显示）；③ `chars` 补登记 6 处（23/24/25/26/27/38；既有字段、零语义；见 §7.6）；④ `choice.sayKind` 可选覆盖（`'fail'`｜`'info'`，默认不写；见 §3）；⑤ `characters[].img`（图鉴/人物卡真头像；见 §7.6）；⑥ `scenes.<sid>.figures`（L1 常驻角色可见轮廓框——覆盖卡几何的唯一来源；标定流程；见 §7.3）；⑦ `scenes.<sid>.variants`（背景状态变体——条件驱动的 L1 换图；先匹配者为准；见 §7.10）。其余全部用现成字段与渲染层完成。理由与边界逐条写在 §7。
3. **一屏原则**：任何时刻首屏要能同时看到——资源读数、场景与在场人物、正文、可点选项；新增的反馈区与物品栏都不许把选项挤出首屏。
4. **颜色必有冗余**：颜色只作第一眼区分；每一类消息同时带**图标 + 前缀词 + 固定位置**三件冗余，色盲玩家不靠颜色也能分辨（见 §3）。
5. **改动可机检**：颜色触发条件、弹框时长、物品栏内容、氧气数值与条的同步关系，全部写成可断言的判据（见 §3~§6 各表「机检」行）。

### 1.1 关卡选择页（启动页 · B115／B117）

> B115（2026-10-03）：难度改单选（默认普通）＋唯一「开始」。**B117（2026-10-04 老板裁定）：存档＝浏览器本地、各人各份 ⇒ 读档功能保留；一局结束（通关／失败终止）后不得出现「继续上一次」；新增通关记录。**

**存档口径（明写）**：存档＝**浏览器本机存储**（localStorage，按关卡一键）——**各人各份**：换设备／换浏览器＝另一份；网上发布时每台机器各自一份；**无服务器、无账号同步**。通关记录单独存本机（独立键；开新局覆盖存档不影响它）。

**卡片三态（按本关存档与记录渲染）**

| 状态 | 按钮 | 记录块 | 说明 |
|---|---|---|---|
| 无存档 | 唯一主按钮「**开始**」 | 有通关记录时显示 | 开新局（沿用 B115）；无覆盖确认 |
| 有未结束存档 | 主按钮「**继续**」（点击＝载入该存档、回到存档节点）＋次按钮「**重新开始**」 | 有通关记录时显示 | **不出现「开始」**；「继续」不受难度选择影响（存档自带难度） |
| 该局已结束（通关／失败终止） | 主按钮「**重玩**」 | **必显示** | **不出现「继续」**——结束局续玩＝直接看结局，无意义（老板原话） |

- **结束判定**：存档节点为 `win`／`fail` 节点（41/42/43／44／29）或 `st.bankrupt` 为真 ⇒ 该局已结束。
- **通关记录块**：① 通关史（独立键）：`🏆 通关记录：结局 · 圆满`——多个已收集结局并列（如 `…：结局 · 圆满、结局 · 取舍`），按达成先后、去重；② 本局失败终止（存档为 fail 态）另起一行：`上局结束：未通关`。失败不写入记录、不清空已有记录。
- **覆盖口径**：开新局将覆盖已有存档时——先弹**统一一句确认**；取消＝不动存档。**不做自动备份。**
  - **采用句（唯一一句——两处同句）**：`开始新局会覆盖本关的旧存档（通关记录保留）。确定开始？`
  - 两处＝① 卡片「重新开始」／「重玩」；② 局内重开（右上「↺」重开按钮／结局与失败结算的「↺ 重新开始本关」／求救面板「↺ 重开本关」）。
- **存档脚注**：卡片一行小字：`进度存在这台设备的浏览器里（各人各份）`。
- **难度选择**：单选（默认普通）——作用于「开始／重新开始／重玩」开新局；「继续」不受其影响。
- **字样**：全页不出现「继续上次进度」（入口名＝「继续」）。

- 验收（机检）：① 无存档 ⇒ 唯一按钮「开始」；页面无「继续」「重玩」「继续上次进度」字样。② 未结束存档 ⇒ 有「继续」与「重新开始」、无「开始」；点「继续」⇒ 载入该存档（`loc`／资源／道具与存量一致）。③ 已结束存档（通关与失败各一）⇒ **无「继续」**；记录块在（通关＝`🏆 通关记录：结局 · …`；失败＝`上局结束：未通关`）；有「重玩」。④ 覆盖：点「重新开始」／「重玩」先出确认（句＝采用句）；取消后存档不变；确认后按所选难度开新局；**局内重开同句**（机检：两处确认串相等）。⑤ 记录持久：达成 41/42/43 任一 ⇒ 记录追加该结局短名；随后开新局覆盖存档 ⇒ 记录仍在。⑥ 存档与记录只在 localStorage（无网络请求）；键＝关卡存档键＋记录键。

### B102 ② 提示着色 + 弹框延时 + 剧情区反馈区

- **老板原话要点**：选项在右侧、提示只在地图处弹框且太快——弹框保留＋延时；右侧剧情区也要显示对应文字；用颜色区分（蓝＝正常、红＝未达条件、黄＝关键剧情——按其指示「按专业设计，不照搬」）。
- **落点**：§3（颜色语义表）＋§4（弹框与反馈区规则）。
- **改法**：消息分 4 类着色（info 蓝／gain 绿／key 金／fail 橙红）＋既有危险大条；每条带 `data-kind` 与图标/前缀冗余；toast 驻留加长；正文与选项之间新增**反馈区**（同源渲染、节点内常驻到下一次操作）。
- **验收点**：§3 触发 Hook 逐类可机检（learn→key、gain→gain、失败条形状→fail、其余→info）；toast 新时长；反馈区存在且与 toast 同串。
- **影响文件**：`prototype/engine.js`（`toast`/`doChoice`/`renderNode`）、`prototype/style.css`、`prototype/index.html`（反馈区容器）。

### B103 ③ 地图下方横向物品栏

## 3. 提示颜色语义表（B102 · 可机检）

**总规则**：每条玩家可见消息渲染为 `<span class="msg msg-<kind>" data-kind="<kind>">`；颜色只作第一眼区分，**图标＋前缀＋位置**三件冗余保底（色盲友好）。

| 类 | 颜色（token） | 形态冗余（图标/前缀） | 触发条件（Hook · 可机检） | 位置 | 样例（玩家所见） |

| `fail` 未达 | 橙红 `--msg-fail #ff7a59` | 前缀「✕」（UI 层加，不改数据文本） | 选项满足失败条形状：`say ∧ to===当前节点 ∧ ¬fx ∧ ¬once`（B03 失败条 26 条，`design-station-nodes.md` §9.7）⇒ 其 `say` 入本类；显式覆盖＝可选字段 `choice.sayKind`（`'fail'`｜`'info'`，默认不写） | toast＋反馈区 | 「✕ 你推了推门——锁着。」 |
| `danger` 危险 | 红 `#e63946`／绿（被挡下） | 大号条＋既有文案 | `en.thief`（被偷）／`ifNoItem`（被挡下）——既有 `st.flash` | 剧情区顶部大条（既有） | 「🥷 桑尼的无人机 偷走了你 8 枚星币」 |

**要点**

- 颜色**不照搬**老板举例的蓝/红/黄三分：增加「获得」一类（绿），且「未达」用橙红（与致命红 `danger` 在色相与位置上双区分——danger 走顶部大条、fail 走小消息）。
- 冗余三件套：① 图标/前缀（上表）；② `data-kind` 属性（DOM 机检用）；③ 位置（fail/key/gain 进常驻反馈区，见 §4）。
- 语义判据「fail＝玩家尝试后没做成」与 B03 新哲学一致（条件不足不上按钮，失败在剧情里反馈）；本表只给它**配色与落位**，不改任何文案。

**机检断言（实现轮）**

1. 每条消息节点带 `data-kind` 且 ∈ {info, gain, key, fail}；
2. **fail 双向断言**：① 正——26 条失败条（`design-station-nodes.md` §9.7）的 `say` 均渲染为 `fail`（按上表形状枚举）；② 反——渲染 `fail` 集与 26 条集合**两向相等（零多报）**：形状命中但非失败条者（零代价、原地、带 `say` 的成事条）须以 `sayKind:'info'` 在数据面显式归位，断言以归位后的数据为准；
3. `fx.learn` 产出均渲染为 `key`；`fx.gain` 均渲染为 `gain`；
4. CSS 中 `.msg-info/.msg-gain/.msg-key/.msg-fail` 四类颜色互不相同，且 `:root` 有对应 token。

## 4. 弹框（toast）与反馈区规则（B102）

**数字口径（改自现状）**：现状 toast 缺省驻留 3.4s（`engine.js:700`）、`say` 用 6s；老板反馈「太快」。

| 项 | 规则 |
|---|---|
| 时长 | `info`/`gain`＝**4.2s**；`key`/`fail`＝**7.0s**（信息量最大的两类给足阅读时间） |
| 同屏条数 | toast 同屏最多 **3 条**；超出时最早一条立即淡出（不堆叠遮挡） |
| 去重① | 同一次操作的 `say` 与效果日志文本相同 ⇒ 只显示一次（E7 既有口径，保持） |
| 去重② | toast 与反馈区**同源**（同一消息数组渲染两处），同文本不二次生成 |
| 去重③ | 同一节点内重复点同一失败条：toast 每次重新弹（操作要有回声）；反馈区**原位刷新**，不叠新行 |
| 反馈区位置 | 剧情区内、**正文与选项之间**（正文的下一条读得到） |
| 反馈区内容 | 最近一次操作的完整消息组：`say`（若有）＋效果行，合计 **≤4 行**；无内容时不占位 |
| 反馈区清空 | 进入新节点（`st.loc` 变化）或重开本关时清空；同一节点内只保留最近一次 |
| 既有警示条 | 被偷/被挡下大条（`#alertBar`）不动——它属于 `danger` 类，位置在顶部，与反馈区不冲突 |

## 5. 物品栏规格与交互（B103）

**位置**：场景区底部（地图正下方，桌面与移动端同一条），横向排布；条目多时横向滚动。

| 项 | 规格 |
|---|---|
| 条目来源 | `st.items`，按 `itemOrder`（数据既有）排序；**只显示已持有**（未持有不留灰位） |
| 单条形态 | 图标（道具切片）＋名称（≤4 字截断）＋角标：📖＝有正文；「可用」＝当前有唯一消费选项 |
| 空栏 | 显示「（还没有道具）」一行小字 |
| 点选 | 单击展开详情气泡：图标／名称／「📖 看内容」（有正文时）／「可用于：<选项名>」（命中时） |
| 查看 | 有 `text` 的道具 → 打开既有只读面板（E3，不变）；无正文 → 「这件东西没什么可读的」（不变） |
| 使用 | **仅当**该道具在当前节点有**恰好一条可见选项**消费它时出现「使用」按钮：条件＝该选项 `cond` 树（含 `all`/`any` 递归）含 `item:此物` 或 `anyItem` 含此物，或 `fx.lose` 含此物，且该选项可见（`choiceState!=='hide'`）。点击＝执行该选项（与点选项同一路径、同一反馈）。多条命中 → 显示「可用于 N 处」，点击滚动并高亮选项列表；零条 → 不显示按钮 |

| 边界 | **不做**自由使用（不新增「道具→效果」语义）；不为未获得道具留位；不改道具数据 |

**机检断言（实现轮）**：① 任一时刻物品栏条目集＝`st.items` 集、顺序＝`itemOrder`；② 「使用」按钮出现条件与上述判据一致（对 4/13/16/12 等节点抽查）；③ 点「使用」与点对应选项后的状态（资源、道具、去向）逐字一致。

## 6. 氧气读数与其它呈现口径（B104/B109）

### 6.1 氧气＝数值＋条（同源同帧）

- **HUD 形**：`💨 [██████░░░░] 58`——图标＋10 格分段条＋数值。
- **数值**＝当前氧气余量原值（单位「点」，与全部代价/补给同单位：开门 −5、拆芯片 −5、出舱 −15、氧气瓶 +15……玩家可直接心算）。
- **条**＝`round(数值 ÷ 基准 × 10)` 格；**基准＝普通开局值 100**（既有口径；困难开局 30 ⇒ 显示 30、条 3 格——属预期）。
- **档位色**：≥50 正常（绿 `#5ad7a0`）／20~49 警示（黄 `#ffd166`）／<20 危险（红 `#ff6b6b`＋呼吸感）；**数字与条同色**。
- **更新时机**：`renderHUD` 全量渲染；资源变动后数字与条**同一帧**更新；扣/回氧触发闪烁（既有 `barHit`）时条与数字一起闪——两者永不出现「条涨了数字没动」。
- **`--player`（工具面 · 同口径）**：`💨 氧气 ██████░░░░ 58 还好`（文本条＋数值＋档位词）；档位词保留＝颜色档的文本冗余；试玩器与网页同源同值（体验师看到的就是玩家看到的）。
- **边界**：帮助补给行等「效果量」数字保留（`design-station-v1.md` §8.3 口径不变）；开发视图（lab/CLI/JSON）不受限；资源数据与存档不动。

### 6.2 结局名去字母（网页端 · B109）

- 玩家可见处一律「🏁 结局 · 圆满／取舍／撤离」——**去掉 A/B/C 字母**（字母＝结构剧透：会让玩家知道结局有编号）。
- 实现面＝渲染层变换（`node.endTag` 数据不动；与 `--player` 既有 `playerEndName` 同规则）。
- 机检：结局屏与失败屏渲染串不含 `结局 [ABC]`。

### 6.3 层标与到达提示（B123）

- **层标（沿用）**：场景区左上角标（顶层/中层/底层/站外）——既有能力；房间场景显示**所属层**（不变）。
- **到达提示（B123 · 2026-10-04 定口径）**：场景切换时的 toast（配色归 `info` 类）——
  - 到达**房间场景**（`room-*`）⇒ **`到达：<房间名>`**（例：「到达：食堂」）——**不带电梯图标**；房间名＝场景 `name` 的「·」后段。
  - 到达**非房间场景**（大厅/站外——含楼层间移动，如电梯 18⇄20⇄21）⇒ **保留现形 `🛗 到达：<场景标>`**（例：「🛗 到达：顶层」）。
- **`--player`（工具面 · 同口径）**：试玩器无到达弹框；其场景标与左上角层标同口径（房间场景仍显所属层）——到达提示（房间名）为网页独有面；房间名已由「当前位置」的节点名承担。
- 机检（实现轮）：到达房间的 toast 串＝`到达：<房间名>` 且不含 `🛗`；非房间场景＝`🛗 到达：<场景标>`（现形）。

### 6.4 提示条（hintBar）归位

- 场景底部提示条移入**物品栏行内右侧**（小字）——物品栏不再与提示条叠层；场景图上只保留左上角标与右上按钮两处叠层。

**位置与尺寸（锚点口径）**

- 锚点＝原图像素（与 pins 同口径）：角色图锚在**底边中点**（人物「站」在场景里）；窗景图锚在**窗区中心**。

- 校准：复用既有坐标校准模式（`C` 键 / lab 标定；检测脚本 + 人工复核，与 pins 同流程），数据落 `moments.<id>.at`；显示图更换（内景接线）后重校准。常驻角色轮廓框（`figures`）＝**两点定框**（左上／右下；C 键校准模式扩展为框选，工具面——§11）。

**出现 / 退场**

- 出现：命中即渲染——淡入 0.35s＋上浮 12px；同节点多张依次错开 0.08s。
- 退场：离开节点或条件不再命中 ⇒ 淡出 0.25s 后移除；换场景 ⇒ 清空重渲染；不跨节点驻留。
- 不可点掉、不接收指针事件（与可点掉的 CG 演出浮层是两层）；同节点两者同时命中时，CG 关闭后再淡入浮现图。

**多角色并存**：同节点 ≥2 张分别按锚点摆放；未给锚点时左右对称（中心 ±0.32×场景宽、底边对齐）；互不遮挡、**不盖住编号点**（校准时避让）。

### 7.10 背景状态变体（B122 · 机制 · 最小新增）

> 来源：老板 2026-10-04 裁定②——「浮图+背景图**组合**、结合剧情**灵活改动**」：人物消失／物体被移动／角色离场／状态变化等情况**背景图本身就该变**；浮图只管**剧情推进过程中的动作与表情**，**剧情过之后切到当前状态的背景图，而不是一直盖着**。

**字段（数据面唯一新增第 7 项）**：`scenes.<sid>.variants = [{ cond, image, width, height, figures? }]`

- **判定**：按数组顺序取**第一个 `cond` 命中者**（先匹配者为准——仿 `tIf`／`mIf`）；命中行**完整替换**基础条目的对应字段（`image/width/height/figures`）；全不命中 ⇒ 基础条目（现状）。渲染判据＝数据，顺序敏感。
- **生效面与层序**：变体替换的是 **L1 场景图**本身（`sceneImg.src`＋舞台宽高变量）——**变体生效时 L1 即为新状态**；场景区层序不变（场景图 → 未探索遮罩 → 浮现层 → 编号点 → 角标）；进房与条件变化时逐次求值（与 `renderNode`／`momentsOf` 同帧）。
- **几何（硬约束）**：变体图**必须与基础图同尺寸、同构图、同机位**（pins 与浮现锚点共用）——机检＝`width/height` 与基础条目逐值相等；改变布局者＝另立场景条目（本机制不支持）。
- **与浮现层的协作**：① `figures` 解析＝命中变体的 `figures`（给出时**整表替换**；`{}`＝该状态无同框面）否则基础 `figures`；② **覆盖卡按新状态判**（例：医务室苏醒版 ⇒ 伊莲娜的轮廓框＝苏醒姿；观景厅猫离场版 ⇒ `figures = {}`，无可覆盖对象）；③ **同实体 L2 的注册触发点必须落在「变体已生效」的节点/条件上**（防双现复发——例：`helper-join` 注册 37（en 先置 `机器人小帮手`）；`robot-rescue` 注册 37、16 本体不注册）。
- **命名与入库**：变体图＝`images/station/rooms/<name>-<state>.jpg`（资产 id＝`<name>-<state>`；`<name>`＝基础图文件名段）；**注册前置＝图已入库**（同内景口径）；**免验收直入**（扩图批同款——出图即生效，不走 `art/deliveries/`）。
- **缺图兜底**：运行期加载失败（文件缺失/损坏/路径错）⇒ **回落基础图**渲染（不空白、不破图）＋控制台一行告警；玩法零降级（旧状态图＝可接受回退）。未注册的变体＝不存在（无补丁路径）。
- **读档归一**：变体全部由 `cond` 驱动（**无独立状态位**）⇒ 进房/换场景/读档后按当前 `st` 重算即落位；旧档（无该概念的数据）不受影响。
- **边界**：不新增状态位、不改剧情语义与数值/条件/文案；不改 pins（同构图约束）；不做自由换图（条件驱动的有限清单——§7.11）。

**机检断言（实现轮）**

1. **判定**：状态桩给定 ⇒ 命中第一条满足者；多命中 ⇒ 取首条（顺序敏感）；全不满足 ⇒ 基础条目；
2. **几何**：每条变体 `width/height` 与基础条目逐值相等；`figures`（若有）键 ∈ `characters`、框在变体图界内（卡面连同余量同判）；
3. **兜底**：变体图加载失败 ⇒ 以基础图渲染（DOM 冒烟：`src`＝基础图＋一行告警；无占位框）；
4. **读档**：旧档（无 variants 概念）/新档 ⇒ 场景与变体求值正确（Core 层，无 DOM）；
5. **回归**：无 `variants` 的场景输出与改前逐字一致；示例关零变化；pins／`pinsAll`／覆盖卡几何不受影响（同尺寸断言）。
