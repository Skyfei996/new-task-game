> 归属：本项目**组织与流程的唯一权威**（谁做什么、做到什么算好、怎么交接、怎么隔离）。

## 二、专业标准（分岗位的"什么叫好"）

### 2.1 关卡标准（关卡策划）
1. **动线规则**：纵向移动只能经由**通道**（电梯 / 爬道 / 舱外），且通道**双向**都要有可读说明；禁止"从 A 层一步跨到 B 层"的选项。
2. **留存原则**：任何剧情推进后回到某场景，**本场景的可用选项必须保留**（不得只剩"离开"）。
3. **探索回报**：每个可进入的场景至少有一个"值得进去的理由"（道具/线索/人物/风景）。
4. **一一对应**：节点网络里的每个地点，必须在场景图上有一个编号点；反之亦然；移动文案里的方向感要与图相符。

### 2.2 叙事标准（编剧）
1. **故事圣经**（单一事实源）：角色在场表（谁在哪、什么时候）/ 通道清单 / 动作耗氧表 / 道具因果链 / 人物卡（职业·性格·特点·能力·喜好·口头禅·**不会说的话**）。
2. **信息顺序表**：每个结论出现前，玩家必须**已经看过它依赖的每一个前提**（先见货单，才说得出"对上了"）。
3. **角色声音**：每人的句长、用词、称呼、态度不同；胜、败、被拒、被无视都要有反应。
4. **朗读工序**：对白念一遍；念着别扭就改（不写"说明书腔"）。
5. **名词白名单**：文本里出现的一切专有名词，要么已在别处出现过，要么当场给一句解释。

### 2.3 演出 / 分镜标准（新增；回答"界面怎么变"）
**每个任务点必须填一张"演出表"**（写进关卡设计档，按节点编号落）：

| 列 | 内容 | 例（3 号医务室） |
|---|---|---|
| 背景 | 场景图 + 是否要新图 | 顶层生活区 · 医务室内景（**需新图**） |
| 镜头/焦点 | 首帧焦点、是否推近 | 焦点：病床 → 轻推近 |
| 元素进出 | 道具出现/消失、角色位移、门开合 | 阿雅站在床边；氧气站在墙角发光 |
| 主面板 | 正文位置、是否要特写插图 | 正文在右下；**需要一张"站长受伤"特写** |
| 氛围 | 明暗、色调、天气/粒子 | 冷光 + 应急灯闪烁 |
| **界面变化** | HUD 与反馈：资源警示、物品入包、线索卡、进度 | 交医疗包时：物品飞出 + 获得卡 + 氧气条闪一下 |
| 音效钩子 | 触发点与音色 | 推门"嘶——"；设备"滴答" |

规则：① **没有演出表的节点不许进实现**；② 关键节点（首访房间 / 获得关键道具 / 结局）必须有镜头语言（推近 / 特写 / 黑屏 / 慢镜）；③ **美工任务单从"需要新图/特写"的行自动派生**——剧本一变，任务单跟着变，不再靠人去想。
（未来扩展位：音效列已在表内；战斗节点可加"战斗演出"列——入场、技能、受击、结算。）

### 2.4 UX 标准
任何操作都有反馈；状态变化 0.5 秒内可见；选项优先于装饰；手机竖屏首屏必须能用；被锁选项要么给玩家话的灰显理由，要么隐藏（**规则**：能推进的"另一条路"→灰显；纯粹"还没到时候"→隐藏）。

### 2.5 数值标准
见 `design-station-v1.md` §8（每个数字可复算；循环净收益为负；难度分档有明确余量目标；关键结论进自测断言）。

### 2.6 QA 标准（三线）
- **功能**：可达性、状态机、存档、失败结算；每条缺陷给复现命令。
- **连续性**（五查）：角色在场 / 时间线 / 空间规则 / 因果 / 名词；**任何"操作后画面无变化"必须记为问题**；**任何"角色两地同现"必须记为问题**。
- **体验**：每 15 步日报（我想干什么 / 感受 1~5 / 想不想放弃 / 原话）；每幕复述；报告禁止机制分析、禁止合理化（"这是原型"不是理由）。

## 三、协作流程（谁在什么时候、拿什么、交给谁）

```
① 老板：提出体验目标
      ↓
② 主策划：写需求档（五要素）← 老板批
      ↓
③ 设计三线并行（各自隔离上下文）：
     · 系统+数值线 → 机制表/数值表/预算
     · 关卡线     → 节点网络/动线
     · 叙事线     → 故事圣经/人物卡/信息顺序表/对白
      ↓
④ 演出分镜：拿节点网络 → 演出表（画面/镜头/界面变化/音效钩子）
      ↓
⑤ 设计评审（独立评审 = 方法学 + 手艺 + 一致性 lint）+ 老板审戏剧性
      ↓ 通过 + 老板批准
⑥ 实现（程序/数据）→ 自测全绿
      ↓
⑦ QA 三线并行：功能 / 连续性 / 体验（各自隔离）
      ↓
⑧ 修正 → 复测 → 老板验收
      ↓
⑨ 美工与音效生产（任务单从演出表派生）→ 集成 → 发布
```

| 交付物 | 负责(R) | 批准(A) | 咨询(C) | 知会(I) |
|---|---|---|---|---|
| 需求档 | 主策划 | 老板 | 系统/关卡/叙事 | QA |
| 故事圣经 · 信息顺序表 | 叙事 | 主策划 | 关卡 | 演出 |
| 节点网络 · 动线 | 关卡 | 主策划 | 叙事/演出 | QA |
| 数值表 · 预算 | 数值 | 主策划 | 系统 | QA |
| **演出表** | 演出分镜 | 主策划 | UX/美术 | 程序 |
| 美术任务单 | 美术总监 | 主策划 | 演出分镜 | 老板 |
| 实现 | 程序 | 主策划 | —— | QA |
| 质量报告 | QA 三线 | 主策划 | 叙事/关卡 | 老板 |
| 验收 | 老板 | 老板 | 全体 | 全体 |

## 四、上下文隔离（硬规则）

1. **零上下文启动**：每个角色开一个**独立会话**，启动时只知道自己的简报（目标 / 输入文件 / 验收 / 禁区），**不知道**我们之前的对话、别人的草稿、代码实现。
2. **只走文件交接**：简报里**禁止粘贴对话内容**；要传的东西落成文件（如故事圣经、演出表、任务单），简报只写指针。
3. **玩家向角色只见玩家所见**：QA-体验只能用 `--player`（无编号、无数值、无机械理由）；写报告时才允许用编号定位问题。
4. **评审只见被评物 + 标准**：不给作者的思考过程与辩解（避免"被说服"）。
5. **禁止"原型豁免"**：任何角色不得以"这是原型/测试版/以后再说"为由放过问题；存疑即上报。
6. **写域与只读域声明**：每个角色开工前声明"我能改哪些文件、我只读哪些文件"；越界即停并上报。
7. **同一个产线不做自证**：作者不得给自己的产出做最终验收（验收权在主策划/老板/独立评审）。
